01 — The difference

Every number on this page is traceable to a file

Most portfolios assert impact. This one cites it. Each figure below was extracted programmatically from a reports/*.json produced by a pipeline in a public repository — not typed by hand, and not rounded in my favour.

01

Ground truth is injected, then scored against

Each project's data generator plants a known mechanism — a fraud ring, a concept drift, a causal effect. The analysis is then graded against what was actually planted. "It looks right" is never the standard.

02

A suspiciously good number is treated as a bug report

A 100% score triggers an investigation, not a celebration. Several projects contain a fix and a re-measurement because the first result was too clean — including a PII detector at 1.000 that turned out to be scoring its own training distribution.

03

Refuted hypotheses are reported as results

Where the thing I set out to prove turned out false, the site says so. Arrival-time windowing was supposed to be badly wrong; at realistic parameters it isn't, and the honest finding is the crossover point instead.

04

Reproducibility is measured, not claimed

Datasets are verified byte-identical by SHA-256 checksum in a fresh process — because two projects shipped fixed seeds that still weren't deterministic, and only a new process can catch that.

06 — Background

About

I came to data engineering through customer support operations, which turned out to be an unusually good apprenticeship. Working complaint queues teaches you that a metric is a promise someone is accountable for, that an average hides the cases that actually hurt, and that the number on the dashboard is only as good as the definition nobody wrote down.

That shows up in how I build. Every project in this portfolio starts by asking what would make the result checkable — and several of them exist because the checkable version disagreed with the obvious one.

I work across the whole path: designing the data, modelling the warehouse, building the pipeline, training and calibrating the model, testing it adversarially, and shipping the interface a human actually uses.
